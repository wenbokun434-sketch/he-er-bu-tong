# 录屏与上台演示

双击仓库目录中的 `启动演示.cmd`。脚本自动打开 http://127.0.0.1:5174/?caseId=campus ，保留终端即可使用；Ctrl+C 停止。已安装依赖并构建的本机可以离线彩排。首次下载仍需 npm ci 和 npm run setup。

彩排数据库位于 `.sites-runtime/rehearsal/state`，与 5173 正常试用的 `.wrangler/state` 分开。彩排不读取付费 AI 密钥、不调用付费模型；协商和确认均由人操作。重复双击会打开已经运行的彩排，不启动第二个服务。

## 最短故事

1. 首个议题“时段与资源分配”：起草首个方案 → 填入第一稿示例 → 手动发布。
2. 跟随导演提示切换为文化社团代表，提交“仍有异议”：小众社团也需要基本舞台时间。
3. 回到协调员，修订方案 → 填入修订稿示例 → 手动发布。
4. 根据提示依次切换三个参与方，分别接受当前方案；没有自动确认或代签。
5. 和议书工坊 → 从已确认方案起草 → 填入彩排正文 → 核对来源与正文 → 保存 → 冻结送审。
6. 三方分别阅读并确认整份文书。
7. 承诺追踪 → 展开任务创建，核对预填的负责人、复审人、日期和标准 → 建立任务。
8. 负责人点击“填入完成与验收示例”，核对后提交；复审人点击“填入验收意见示例”，核对后验收通过。
9. 回看保留分歧和操作历史，导出成稿作为结束画面。

示例按钮只填草稿，不发布、不批准。日期根据填入当天的北京时间生成。切换模块前保存草稿。

## 再次彩排

点击“开始新一轮彩排”，核对说明后点击“保存快照并重新开始”。服务器先归档当前案例的四类记录，再原子清空该案例；其他案例不受影响，过期版本请求不能执行重置。上一轮快照保存在彩排数据库的 rehearsal_archives 表，页面提供最近一次快照 JSON 下载。快照保存全部记录；当前没有一键恢复到活动状态的功能。

导演提示根据当前数据判断进度，不会伪造完成。首次提出异议、修订方案、逐方接受、文书送审与确认、负责人报完及复审验收都需要真实操作。

## 其他案例的彩排

返回案例库，选择 OpenAir Watch 或共邻空间，同样显示五阶段导演提示。各案例的全部议题均可填入对应第一稿和修订稿；文书、任务标准与完成依据也使用当前案例内容。OpenAir Watch 以预警频率与社区授权为首个故事，共邻空间以公共通行和合理外摆为首个故事。每个案例单独记录进度、归档与重置。

示例仅填入草稿，发布方案、逐方确认和验收仍由演示者操作。遇到启动异常，窗口会保留；日志位于 heyi-os/.sites-runtime/rehearsal/launcher.log。HTML 入口不直接启动 Node 服务，首次使用请先完成依赖安装和构建，再双击启动演示.cmd。
