# 和议书 · HeYi OS

把“和而不同”落实为可讨论、可追溯、可执行的合作规则。三方保留不同需求，通过共享画像、会议讨论、动态差异地图和方案表态形成和议书，再追踪承诺的执行与复审。

这是可独立在本机运行的网站源码，不需要安装 Codex，也不需要登录 Cloudflare。首次安装需要联网；AI 功能额外需要自己的有效 API 密钥与额度。

## 快速开始

准备 Node.js **24**（测试版本 24.19.0，自带 npm）及现代浏览器。项目声明最低 Node.js 22.13，但本次验收使用 24。Windows 建议使用 PowerShell。Git 不是必须：也可以在有仓库权限的 GitHub 账号中选择 **Code → Download ZIP**，解压后打开终端。

在包含本文件和 `package.json` 的 **heyi-os 目录**执行：

```sh
npm ci
npm run setup
npm start
```

浏览器访问 **http://127.0.0.1:5173**。保留运行中的终端，按 Ctrl+C 停止。以后再次打开只需 `npm start`；修改源码或更新版本后重新执行 `npm run setup`。

`setup` 会构建页面与后端，应用尚未执行的 5 份数据库迁移。重复运行不会清空已有数据，也不会重复建表。所有数据库操作都固定为本地模式，不会连接原作者的线上数据库。请勿把这套迁移脚本直接用于此前手工导入过 SQL 的旧数据库。

端口被占用时：

```sh
npm start -- --port 5174
```

## 真实 AI（可选）

未配置密钥时，案例、画像、会议消息、差异地图、方案确认、和议书、承诺追踪仍可使用。AI 会明确提示未配置，不伪造模型回答。

1. 将 `.env.example` **复制**为同目录下的 `.env.local`（Windows 留意不要保存为 `.env.local.txt`）。
2. 用文本编辑器在 `.env.local` 中填写自己的 `ACCTOKEN_API_KEY`。
3. 保持以下地址与模型配置，重启 `npm start`。不要把真实密钥填进 `.env.example`、网页聊天或 GitHub。

```dotenv
ACCTOKEN_API_KEY=在此填写你自己的密钥
ACCTOKEN_BASE_URL=https://www.acctoken.com/v1
ACCTOKEN_MODEL=deepseek-v4.1-flash
```

当前实现使用 **ACCTOKEN 第三方服务的 `/v1/responses` 接口**，不是 DeepSeek 官方直连，也不是任意 OpenAI 兼容地址的通用适配器。服务端只允许已告知的服务商地址；更换服务商需同步修改接口适配与用户同意说明。

点击发送给 AI 前，用户必须确认将问题、已共享的画像、议题、方案、会议消息和有限的 AI 历史交给该服务商处理。不要输入真实患者信息、个人敏感数据或保密资料。密钥只由服务端读取；每分钟最多 6 次、24 小时最多 60 次是调用限制，不是金额封顶。调用费用、模型可用性和额度取决于你自己的账户。

AI 可以分析冲突、引用依据、提出澄清问题和待审核关联；**不能替任何参与者批准方案或和议书**。当前 AI 也不会自动执行外部项目中的任务。

## 如何使用

1. 选择案例：OpenAir Watch 跨国预警合作、校园文化活动、社区协商三个预设案例相互隔离。
2. 使用演示角色切换器，分别填写三方愿意共享的目标、担忧、底线和可协商条件。
3. 在协作会议室讨论；在不同标签页选择不同角色，观察共享消息的轮询更新。
4. 在动态差异地图中核对“需求 → 议题 → 方案”的关系和证据；AI 建议须由人审核采纳。
5. 提出方案，写清谁负责、做什么、何时执行、适用条件、如何复审，再由三方分别表态。
6. 在和议书工坊补全文书、保存版本并送审。三方分别确认后生成正式成稿，可导出 HTML、Markdown，或通过浏览器打印保存 PDF。
7. 从文书条款创建承诺任务，设置负责人、验收人、期限和标准；更新进度与依据，验收、退回或重开复审。

完整示例发言与录屏步骤见 [Demo 录制说明](docs/和议书-Demo录制说明.md)，现场演示见 [速查表](docs/和议书-Demo现场速查.md)。示例属于虚构教学材料。

## 数据、安全与使用边界

- 每份安装拥有独立数据库；不会下载作者的聊天、和议书、任务或 API 历史。案例的初始说明与画像是程序内置的教学设定。
- 同一个本地服务器中的同一案例共用状态，不是每位访问者独立的房间。
- **角色切换器是演示功能，不是账号登录或安全身份认证。** 页面操作规则不等于防止恶意用户伪造角色的权限系统。不要将本版本直接暴露到公网或用于真实机密合作。
- 默认只监听 `127.0.0.1`，适用于同一电脑多标签页演示；不同电脑下载后各自的数据不会互通。真正跨电脑协作需部署到同一个受保护的服务器，并补齐账号、授权和运维。
- 本地数据保存在 `.wrangler/state/`。停止服务器后可复制整个目录备份。需要重新彩排时，先停止服务，将该目录改名保存，再运行 `npm run db:migrate`，最后 `npm start`；旧目录可恢复，勿直接删除唯一备份。
- 自动化接口测试使用 `.sites-runtime/integration-*/` 的独立数据，不会清空你的正常演示数据；也不会调用付费 AI。
- 本仓库不包含作者的密钥、原 Sites 项目 ID、线上数据库或本地 Git 历史。`.env.local`、运行日志和数据库均被忽略。
- 这是课堂协作原型；文书确认属于应用内流程记录，不是实名认证、可信电子签章或法律效力保证。界面展示的执行动作需要参与者在现实中自行完成。

## 开发与自测

```sh
npm test
npm run typecheck
npm run test:integration
```

接口测试前需先运行 `npm run setup`。测试会自行启动/停止一个本地服务器，验证数据库迁移、案例隔离、方案与文书确认、文书导出和承诺任务等；不消耗 API 额度。

开发热更新：先完成 `setup`，再运行 `npm run dev`（默认 5173），不要与 `npm start` 占用同一个端口。录制与稳定演示推荐 `npm start`。npm 锁文件是依赖版本依据，不要混用其他包管理器更新锁文件。

技术：React + TypeScript、Vinext/Vite、Cloudflare Workers 本地模拟、D1/SQLite、Drizzle、Tailwind。关键目录：

| 目录 | 内容 |
| --- | --- |
| `app/`、`components/` | 页面、组件和服务器 API |
| `lib/` | 案例、协商、地图、AI、文书与任务规则 |
| `db/`、`drizzle/` | 数据库模型与不可重复修改的迁移 |
| `scripts/local.mjs` | 跨平台本地初始化与启动 |
| `tests/` | 业务规则与接口回归测试 |
| `docs/` | 录制材料、验收与运行说明 |

这是带数据库和服务端 AI 的全栈网站，**不能仅上传 GitHub Pages 当静态页面运行**。如需云端部署，需要兼容的 Workers/D1 运行环境、独立数据库、密钥配置与完善的身份权限；本仓库没有附带作者的云端项目身份。

## 常见问题

- `npm` 找不到：安装 Node.js 24 的完整发行版并重新打开终端，确认 `node -v`、`npm -v` 有输出。
- PowerShell 拦截 `npm.ps1`：在相同命令位置使用 `npm.cmd`，无需为了项目降低全局执行策略。
- 安装下载失败：检查网络与 npm 源，使用官方 npm registry，重试 `npm ci`，不要禁用 TLS 校验。
- 提示先构建、缺表或页面 503：确认终端进入 `heyi-os`，运行 `npm run setup`，查看是否出现迁移成功。
- AI 未配置：检查 `.env.local` 文件位置、变量名、后缀，并重启服务器。401/403、额度不足或模型不可用应在服务商账户解决；不要公开密钥截图。
- 明明有 API 配置却无法联网：本机代理、防火墙及服务商状态会影响模型调用；其余协作功能无需调用该 API。
- 文书不能送审：按页面补齐必填项并确认来源方案没有变化；三方确认与字段完整是两个不同条件。
