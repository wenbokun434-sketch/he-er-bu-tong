# 和议书工坊与承诺追踪验收

## 一次完整演示

1. 进入任一案例，在差异地图发布五项齐全的方案，并切换三个参与方分别接受。
2. 进入和议书工坊，选择“从已确认方案起草”。补充共同目的、范围、适用期、保留分歧、复审、异议暂停和退出交接安排。没有填完也可先保存共享草稿。
3. 保存固定版本，检查来源快照。缺项时不可送审；全部填齐后点击“冻结并送审”。
4. 切换三个参与方，逐一阅读并确认整份文书；协调员不能替三方确认。修订意见不会被当成接受。
5. 下载 HTML 打印版或 Markdown。HTML 可通过浏览器打印为 PDF；不是直接生成的 PDF，也不是电子签署。
6. 进入承诺追踪，从当前有效文书条款建立任务，核对负责人、不同角色的复审人、截止日、验收日和标准。
7. 切换负责人，填写操作说明，更新进度、标记受阻或提交完成依据，申请验收。
8. 切换指定复审人，核对依据并通过，或退回补充。只有通过验收才显示“已验收”。
9. 测试改期原因、取消/恢复，以及已验收任务的复审重开；检查履约历史。

## 数据与保护

- [ ] 刷新或重新打开案例后，草稿、成稿、任务与历史仍在。
- [ ] 原样保存文书不产生新版本，不改变确认；真实修改形成新草稿，需要再次送审。
- [ ] 历史版本正文不被后续编辑覆盖，导出包含版本状态、来源快照与逐方意见。
- [ ] 新草稿不取消旧成稿的执行资格；新成稿三方确认后替换旧版作为执行依据。
- [ ] 来源方案、共享立场或原方案接受状态变化后，文书提示待复审；旧任务禁止新申请或通过验收，历史仍保留。
- [ ] 不同案例不能读取、导出或操作另一案例的文书和任务。
- [ ] 两窗口同时修改时，迟到操作被拒绝并保留输入，不覆盖另一方更新。
- [ ] 不能以协调员身份批准整份文书，不能替任务负责人提交进度，不能自行验收。
- [ ] 日期真实有效，验收不能早于截止日，过期与到期提示按北京时间更新。

## 边界

角色仍是演示切换，不是经身份验证的签署或项目权限。每条文书条款建立一项主承诺；材料依据为文字、记录编号或链接，尚无附件上传。系统不自动核实材料，也不发送离线推送或邮件。任务排期不修改原文书约定；超出约定时须修订文书并重新确认。文书和任务未接入新的 AI 自动批准、指派或调用流程，不产生额外模型调用。

## 自动检查

运行 `node --experimental-strip-types --test tests/*.test.mjs`。隔离本地生产预览启动后，设置 `HEYI_TEST_URL` 为本地地址，再运行 `node --experimental-strip-types tests/workflow-api.mjs`。脚本会写入本地测试数据，拒绝线上地址。现有协作、地图和案例接口验收脚本使用同一环境变量。
